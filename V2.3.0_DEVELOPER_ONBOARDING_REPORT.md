## 1. Onboarding Objective

This report evaluates the developer onboarding experience for prospective contributors, users, and researchers discovering QuantsMind's public projects. The goal is to provide a clear, usable path from discovery through first-use to contribution, without enabling GitHub Discussions or changing repository permissions.

**Key Principle**: Evidence-based onboarding. All routes and links are verified against actual repository content. No artificial engagement measures (stars, forks, download counts) used as primary onboarding metrics.

**Scope**: Four public repositories onboarding paths:
1. `.github` — organization profile (entry point)
2. `microquantum` — quantum computing SDK
3. `QuantsMind-SDK` — scientific computing SDK
4. `Karkain` — systems programming language

## 5. Contribution Expectations

| Repository | Contribution Workflow | Maturity-Appropriate Expectations |
|------------|----------------------|-----------------------------------|
| **microquantum** | Fork → feature branch → `pytest` + `mypy` + `ruff` → PR | Mature (GA v1.1.0); full test suite; type checking; linting gate |
| **QuantsMind-SDK** | Fork → `pre-commit install` → `pytest tests/unit` → PR | Stable (v1.1.0); unit tests; dependency rules; package standards |
| **Karkain** | Fork → `develop` branch → `go test` suites → PR | Stable (v1.1.0); phase-gated (`TestPhase115`); lexer/parser/codegen/pm test suites; LSP contribution |

**Contribution Expectations by Maturity**:
- **GA/Stable repos** (microquantum, QuantsMind-SDK, Karkain): Expect PRs to pass full test suites, type checks, and linting. Review within 14 days. No unsupported support commitments beyond issue tracking.
- **In-development repos** (Bio Intelligence, Aerospace Intelligence — not yet public): Contribution guidance would follow similar patterns once public; not applicable currently.

**No unsupported support promises**: Contribution expectations are grounded in each repo's actual CI/test/contribution infrastructure. No commitment to respond within SLA or provide regular releases beyond what the project's own roadmap provides.
